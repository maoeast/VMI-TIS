# VMI-TIS 项目速览（费曼版）

> 这是一份**阅读导览**，不是规范文件。出现冲突时，以 `AGENTS.md`、`docs/vmi_tis.md`、`docs/PROGRESS.md`、`.continue-here.md` 为准。
>
> 目标：让第一次接触项目的人在 10 分钟内知道“它是什么、怎么转、现在到哪、以后往哪走”。

## 一句话版本

VMI-TIS 是一套给特教/康复机构用的**“评估—定级—训练—家校—数据”闭环系统**：先用四层评估找到孩子的起点，按 L0–L5 定级，再按级选操作卡上课；红区、护眼、晋级、连续 0 分四条护栏保证不跑偏；教师、学生 Pad、家长三端共用一套 React 代码，数据留在机构内网。

## 先把术语翻译成人话

| 术语 | 大白话 |
|---|---|
| VMI | 眼睛看到 → 大脑处理 → 手做出来，这三步的配合能力 |
| 四层评估 | 从“身体底座”到“课堂应用”逐层往下查，不是一上来就练 |
| L0–L5 | 六级训练台阶，不是智商或医学分级 |
| R1–R4 | 四条安全护栏：红区、连续 0 分、晋级、护眼 |
| IEP / ITP | 一人一案的教学计划 / 训练计划 |
| 五段式课堂 | 把一节课拆成固定五个环节，逐段记录 |
| 红区 | 发现眼科/视光危险信号，先转介、先锁定高强度训练 |

## 1. 它解决什么问题

孤独症学生常见的问题不是“不努力”，而是“看得见、看不准、手跟不上”。传统做法容易变成三件事各干各的：

- 评估做完了，结果留在纸上；
- 上课靠老师经验，今天练什么、明天练什么说不清；
- 家庭练习接不上，机构里会、回家就不会。

VMI-TIS 要做的，是把这三件事串成一条线：**评估结果直接决定训练起点，课堂记录直接决定能不能晋级，家庭打卡直接进入晋级条件，最后所有数据留下来做画像和科研导出。**

边界也要说清楚：它是**机构内部工具**，数据留在机构内网或单机，不引入云账号和外部数据上报。它做筛查、训练支持和转介提醒，**不是医院诊断设备**；发现红区只负责锁定训练并生成转介单，最终诊断由眼科/医生完成。

## 2. 系统怎么转起来

一条主线，七步：

1. **入案初筛**：红区眼病指征、0–6 岁发育里程碑、日常视觉行为筛查。
2. **四层评估**：视光与眼动、视觉感知、视觉运动整合、课堂应用；用 Beery VMI-6、TVPS-4、MVPT-3、DEM、NPC、NSUCO 这些工具。
3. **红区分流**：发现屈光参差、斜视/复视、遮盖试验异常、眼球震颤等，锁住高强度视觉训练，生成转介单；回执审核通过变绿区，才允许排课和训练。
4. **L0–L5 定级**：按“先稳身体、再练眼动、再练看图、再练手眼、再进课堂、最后进生活”的顺序定起点。
5. **IEP/ITP 一人一案**：选操作卡、定每周频次、定数字训练上限。
6. **五段式课堂**：教师按固定五段上课、记回合、记提示层级；系统守护眼和晋级条件。
7. **家校协同与数据画像**：家长打卡/视频，教师回复；数据进入分析、报告和科研导出。

权威口径在 `docs/vmi_tis.md`；本文件只解释“为什么这样设计”。

## 3. 三端各干什么

| 终端 | 路由 | 主要工作 |
|---|---|---|
| 教师工作台 | `/web` | 学生档案、评估、IEP、排课、课堂记分、操作卡、分析、审计 |
| 学生 Pad | `/student` | 四款 Canvas 训练游戏；另有“评估题卡出示”模式 |
| 家长端 | `/parent` | 家庭作业打卡、视频上传、教师回复、家长留言 |

三端是同一份 `apps/web` 的按路由分终端；Web 和 Android APK 用同一套 React 代码构建。

## 4. 四条护栏，为什么必须有

- **R1 红区熔断**：有眼科红区指征的学生不能排课、不能启动训练；红区项由服务端重新计算，不信任客户端结论；回执上传/审核要校验红区单、回执和当前状态。
- **R2 连续 0 分中止**：连续 3 题 0 分立即中止量表，并保留本轮进度；状态键必须含学生、评估阶段、会话。
- **R3 晋级**：连续 3 次课 ≥80%、至少 2 种材料、至少 1 次家庭打卡，才进入“待晋级”；只统计最近一次晋级审批之后完成的课次，审批前重新核验。
- **R4 护眼硬锁**：数字训练累计 900 秒硬顶；20 秒远眺只关闭遮罩，不重置本课额度；教师重置必须提供服务端授权码。

这四条不是“建议”，是项目红线。它们把“训练有效”和“训练安全”分开：先保证不出事，再谈练得好不好。完整语义见 `AGENTS.md` 与 `docs/vmi_tis.md`。

## 5. L0–L5，用盖房子打比方

- **L0** 打地基：坐稳、头颈稳定、四点支撑；
- **L1** 修眼动：追视、扫视、调节、聚散；
- **L2** 练看图：图形背景、空间位置、视觉记忆；
- **L3** 练手眼：临摹、精细操作；
- **L4** 搬进教室：看黑板抄写、文具使用；
- **L5** 搬到生活：穿衣、系鞋带、超市按清单找物。

定级顺序不能倒：底座不稳就先稳身体，眼动不稳就先练眼动，直接上“手眼整合”往往练不动。具体阈值和公式只在评估种子里，后端不复制第二份。

## 7. 远期目标

分三层看，不要把“远期”误解成“下一轮就做”。

### 产品目标

把“评估 → IEP/ITP → 五段式课堂 → 家校协同 → 数据画像/科研导出”做成真正可用的闭环，让机构里每个孩子都有一份可追踪的干预档案，让老师少凭感觉、多按证据走。

### 交付形态

- Windows 单机版：SQLite，适合小机构/单机演示；
- 医院/服务器版：PostgreSQL 15 + Docker Compose；
- Android Pad：Capacitor APK，学生端全屏低刺激；
- 数据边界：留在机构内网或单机，不做云账号、不做外部上报。

### 要补的工程能力

这些是已知欠账，不是当前轮次的新发现，每一项都应单独立项：

- 眼动仪 60Hz 桥接；
- Android Kiosk 退出码锁；
- 真正的 RBAC 角色权限；
- PDF 报告（当前是 HTML）；
- R2 状态持久化（当前进程内存、单实例）；
- 便携 Node 打包；
- `npm audit` 43 项（1 critical）治理；
- Docker 端口冲突处理。

## 8. 边界与已知欠账

- **不是诊断系统**：筛查和训练支持，不替代医院诊断。
- **不是云产品**：不引入云账号、外部埋点、外部数据上报。
- **不是通用特教平台**：聚焦视觉运动整合这条主线，不扩成万能康复系统。
- **不能把“构建通过”说成“现场可用”**：无设备/无浏览器时，交付报告必须写“未验证”。
- **评估公式只有一个源**：`packages/shared-types/src/vmi_tis_assessment_scales_seed.ts`；禁止重写公式或编造题目。

## 9. 费曼式收尾

这套系统像给特教老师配的**“导航 + 护栏”**：

- 导航告诉你孩子现在在哪一级、下一步该练什么；
- 护栏保证你不会在红区硬练、不会让孩子连续受挫、不会超时用眼、不会在条件不够时误晋级；
- 课后把家庭练习接上，最后把每一步数据留下来，机构才能看见“这个孩子到底进步在哪”。

一句话：**它把“先评估、再定级、按级上课、家校配合、数据留痕”串成一条有护栏的流水线，让干预从经验驱动变成证据驱动。**
