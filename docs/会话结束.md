# 会话结束：最小可恢复交接（VMI-TIS 项目专用）

目标：让下一会话最低成本恢复现场。精简 > 完整，可恢复 > 可读。

## 步骤一：全量覆写 `.continue-here.md`

用完整文件覆写，不保留上一轮的过期状态。模板：

```md
# Current State
- 仓库/分支：<路径、分支、HEAD；Windows 树/ WSL 树关系>
- 工作区：<已修改 / 未跟踪文件；是否 commit/push>
- 验证基线：<命令 + 结果；Node 版本；隔离库/端口>
- 产物/环境：<APK、API、端口、Android SDK、JDK 等当前事实>
- 已知偏差：<沿用项，不要当新发现>

# Next Action
- <下一步唯一原子动作，小到新会话开头可立刻执行；需要用户拍板的写清拍板点>

# Blockers
- <真实阻塞；没有则 None>

# Dead Ends
- <真实尝试过并失败的路径（方案 + 为什么不行）；没有则 None>

# Key Decisions
- <只保留影响后续实现的决策>

# Relevant Files
- <下一步真正会打开的最小文件集>
```

规则：

- `Next Action` 必须是原子操作，不写“完成某模块”这类阶段目标。
- `Relevant Files` 只列下一步真会打开的文件，不列背景材料。
- `Dead Ends` 只记真实尝试过并失败的路径，不写假设性选项。
- 当前状态写事实（路径、HEAD、端口、数量、验证结果）；历史过程写进 `docs/PROGRESS.md`，不要塞进 `.continue-here.md`。

## 步骤二：文档与状态检查

- 本轮完成/验证/偏差追加到 `docs/PROGRESS.md`（历史日志；只追加本轮事实，不改写旧记录）。
- 需求、业务规则或交付口径变化 → 更新 `docs/vmi_tis.md` 的拥有章节；不要在新文件里复制同一规格。
- 任务卡范围变化 → 更新 `docs/IMPLEMENTATION_TASKS.md` 对应 Task。
- 红线、技术栈冻结项、质量门禁变化 → 更新 `AGENTS.md`（同步 Coding Rules / Quality Gates）。
- 新增文档 → 在 `docs/index.md` 登记；失效的活口径直接删除，历史留在 git / `PROGRESS.md`。
- 检查 `docs/index.md`、`docs/会话启动.md`、`.continue-here.md` 三处的当前状态是否一致；矛盾时以 `.continue-here.md` 为准，并修正另外两处。

## 步骤三：Git 处理

```bash
git status --short --branch
```

| 情况 | 操作 |
|---|---|
| 本轮任务完整、门禁全绿，且用户已放行 | 按 `AGENTS.md` 的提交格式精确 commit（`feat(scope): 摘要` / `fix: 摘要` / `test: 摘要` / `docs: 摘要`） |
| 本轮任务完整、门禁全绿，但用户未放行 commit | 不提交；保留工作区，按 `.continue-here.md` 交接，并明确告知用户待放行 |
| 本轮任务未完成 | 不提交、不 stash；通过 `.continue-here.md` 交接 |
| 无关改动 / 来源不明文件 | 跳过并说明原因；不得覆盖、清理或顺手提交 |
| 尚未 `git init` | 跳过提交，说明现状（当前项目不适用） |

规则：

- 禁止 `git add .`；只允许精确 `git add <file>`。
- 提交前门禁：Node `v20.20.2` 下 `npm run verify:all` 全绿；前端 `npm run build` 通过；改了 Android 再跑 `./gradlew assembleDebug`；改了 Docker/部署再实测 `/api/health`。
- 不提交：`.env`、`local.properties`、`node_modules/`、`apps/web/dist/`、`apps/api/data/`、`prisma/.generated/`、`apps/web/android/app/build/`、`*.db`、`*.log`、`*:Zone.Identifier`。
- `push` 需用户单独确认；失败时保留本地 commit 并停止，不强行改写远端。
- 不执行 `npm audit fix --force`；不在未确认 3000/5432 端口时 `docker compose up`。

## 步骤四：覆写 `docs/会话启动.md` 的 HANDOFF 区块

用 Edit 工具覆写 `docs/会话启动.md` 中的 HANDOFF 区块。

定位方式：`old_string` 匹配整个 `<!-- HANDOFF:START -->` 到 `<!-- HANDOFF:END -->` 块（含两端注释行），`new_string` 替换为新内容并保留两端注释行。

模板：

```
<!-- HANDOFF:START -->
## 本次交接（自动生成，请勿手编）
- 当前任务：<精确一句话>
- 下一步唯一原子动作：<取当前 .continue-here.md 的 Next Action>
- 相关文件：<取 Relevant Files 最小集>
- 验证命令：<做完后第一条真实命令>
<!-- HANDOFF:END -->
```

规则：覆写后确认区块完整（两端注释行都在），不要额外追加。

```
Done: <完成项>
Blocker: <阻塞项 / None>
Next: <唯一原子动作>
Repo: <clean / dirty / stashed / no-repo>
```
