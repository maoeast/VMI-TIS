## 二、需求文档分析 (vmi_tis.md)

### 2.1 核心业务流程

#### 阶段1：初筛与红区识别
- 入案时填写《视光与发育筛查表》
- 系统自动判定红区标识（屈光参差、斜视、先天眼病等）
- 红区学生自动生成《眼科转介单》并暂停训练

#### 阶段2：基线评估
- DTVP-3 发展性视知觉测试
- Beery VMI 视觉运动整合测试
- Age Duane调节尺测试（针对调节/集合不足）
- 系统自动计算标准分并生成能力等级（L0-L5）

#### 阶段3：IEP目标制定
- 根据评估结果自动推荐操作卡序列
- 治疗师审核并调整训练计划
- 每周课表自动排期（与学校/康复中心课表联动）

#### 阶段4：训练实施
- **课堂训练**（1对1或小组）：治疗师使用记分台实时记录
- **数字化训练**：投屏至学生端iPad执行游戏化任务
- **家庭作业**：家长端每日5-10分钟打卡练习

#### 阶段5：数据追踪与复评
- 实时监控三次移动平均正确率
- 达标后触发晋级流程（自动推送待办事项）
- 每8周强制阶段复评（重新测试基线量表）

### 2.2 核心数据结构

**学生档案字段：**
```javascript
{
  id: "stu001",
  name: "林小宇",
  age: 8,
  grade: "小学二年级资源教室",
  level: "L2", // L0-L5能力层级
  status: "active", // active/paused/discharged
  redFlags: [], // 红区标识数组
  baseline: {
    dtvp3: { raw: 85, std: 7 },
    beeryVMI: { raw: 48, std: 6 },
    npc: "14cm" // 集合近点
  },
  currentIEP: {
    startDate: "2026-09-01",
    targetCards: ["3-1", "3-2", "3-3"],
    weeklySchedule: [...]
  },
  sessionHistory: [...], // 每次课堂记录
  assessmentHistory: [...] // 评估记录
}
```

**操作卡数据结构：**
```javascript
{
  id: "L2-3-1",
  level: "L2",
  domain: "视觉感知",
  name: "图形-背景识别",
  materials: ["镊子", "珠子", "底板"],
  digitalGame: "找星星游戏",
  passCriteria: "连续3次正确率≥80%",
  parentVersion: "找袜子泛化任务"
}
```

### 2.3 关键算法

**能力层级自动评级算法：**
```
IF (DTVP-3标准分 < 4 OR Beery VMI标准分 < 4)
  THEN L0 - 身体准备期
ELSE IF (集合近点 > 10cm OR 调节幅度异常)
  THEN L1 - 视觉效率期
ELSE IF (DTVP-3 视觉-运动速度 < 7)
  THEN L2 - 视觉感知期
ELSE IF (Beery VMI < 8)
  THEN L3 - 视觉运动整合期
ELSE IF (DTVP-3 所有分测验 ≥ 8)
  THEN L4-L5 - 适应应用期
```

**晋级触发条件：**
- 目标操作卡连续3次课堂记录正确率 ≥ 80%
- 且完成家庭泛化任务验证（家长端上传视频）
- 系统自动推送至治疗师待办，需人工审批确认

## 三、设计方案要点（Word文档）

### 3.1 系统定位
- **目标用户：** 特殊教育学校、儿童康复中心、资源教室
- **核心价值：** 替代纸质操作卡档案，实现数字化全流程管理
- **商业模式：** 医院/机构采购（¥12800/站点/年）+ 家长端免费配套

### 3.2 技术架构建议
- **前端：** Vue 3 + Element Plus + ECharts
- **后端：** Node.js + Express + MongoDB
- **家长端：** 微信小程序 / H5响应式
- **学生端：** iPad原生应用（iOS）或Electron桌面应用

### 3.3 硬件集成
- **眼动仪：** Tobii Pro Fusion（通过SDK获取注视轨迹数据）
- **触控一体机：** 学生端训练游戏载体（支持多点触控）
- **打印机：** 自动打印评估报告、转介单、家长通知

### 3.4 权限与安全
- **角色体系：** 超级管理员、科室主任、主任治疗师、治疗师、实习生
- **数据脱敏：** 家长端仅显示自己孩子数据
- **审计日志：** 所有数据修改留痕（WHO / WHEN / WHAT）

## 五、技术改进建议

### 5.1 代码结构优化
**当前问题：** 所有逻辑在单一HTML文件中，维护性差

**建议方案：**
```
/src
  /components   # Vue组件
    /common     # 通用组件（Header, Sidebar, Toast）
    /modules    # 业务模块组件
  /views        # 页面视图
  /store        # Vuex状态管理
  /api          # API接口封装
  /utils        # 工具函数（评级算法、日期处理）
  /assets       # 静态资源
```

### 5.2 数据持久化方案
**当前问题：** 无后端，数据刷新即丢失

**建议方案：**
1. **开发阶段：** localStorage + JSON文件模拟后端
2. **部署阶段：** MongoDB + RESTful API
3. **数据迁移：** 提供Excel批量导入工具

### 5.3 实时通信架构
**用途：** 治疗师Web端 ↔ 学生iPad端 游戏投屏控制

**技术选型：**
- Socket.io（WebSocket封装）
- 消息格式：
  ```json
  {
    "action": "start_game",
    "gameId": "find-stars",
    "studentId": "stu001",
    "difficulty": 2
  }
  ```

### 5.4 响应式设计增强
**当前问题：** 小屏幕下部分元素重叠

**改进措施：**
- 使用Tailwind的 `sm:` `md:` `lg:` 断点更精细化
- 表格在移动端改为卡片式布局
- 侧边栏在手机端改为抽屉式（Drawer）

## 九、风险评估与应对

### 9.1 技术风险
**风险：** 眼动仪SDK兼容性问题  
**应对：** 提前申请Tobii开发者账号，获取Demo进行预研

**风险：** WebSocket在医院内网防火墙被拦截  
**应对：** 提供HTTP轮询降级方案，或配置反向代理

### 9.2 业务风险
**风险：** 治疗师对数字化系统接受度低  
**应对：** 提供线下培训，设计「纸质操作卡扫描导入」过渡方案

**风险：** 家长隐私顾虑（不愿上传孩子视频）  
**应对：** 视频仅存储3天自动删除，提供本地存储选项

### 9.3 合规风险
**风险：** 医疗数据需符合《个人信息保护法》  
**应对：** 数据加密存储，通过等保三级认证，签署保密协议

## 十一、总结与建议

### 11.1 现有原型优势
1. **视觉设计成熟**：深色主题 + 医疗感配色，专业度高
2. **交互逻辑清晰**：多终端切换、学生切换流畅
3. **核心页面完整**：首页信息密度合理，待办提醒醒目

### 11.2 关键短板
1. **缺乏后端支持**：所有数据需持久化存储
2. **评估模块缺失**：DTVP-3 / Beery VMI 电子量表未实现
3. **训练游戏为空**：学生端仅为占位，无可交互游戏
